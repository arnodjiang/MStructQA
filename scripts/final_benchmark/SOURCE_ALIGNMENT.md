# Source alignment and artifact reuse

Every image, question, reference answer and localized variant must derive from
the same original entry. Source correspondence is a mechanical property; it does
not establish that a reconstruction is faithful or that the upstream answer is correct.

## Offline audit

```bash
python -m scripts.final_benchmark.audit_alignment \
  --dataset data/benchmark \
  --report reports/source_alignment.json \
  --run data/evaluation/model_run
```

`--run` may be repeated or omitted. The audit never calls a model or changes the
dataset. It checks the exact raw Parquet row, original QA, original image bytes,
case identities, normalization/translation request and result records, query
polishing inputs, embedded renderer constants, exported variants, validation
records and saved evaluation requests. It exits nonzero on correspondence errors.
Missing legacy evidence is reported separately. Existing semantic audit failures
are counted separately and must not be interpreted as source-entry mismatches.

## Construction safeguards

- `source_binding` records case ID, base ID, raw-file/row/slot, original image hash
  and source-record/question/answer hashes. Existing source copies are checked
  before reuse. Moving a reserve case into the selection does not alter identity.
- New QA normalization and translation requests carry the source binding and the
  matching original image when one exists. Translation also carries the original
  question and reference answer as meaning checks. Reference answers are never
  used to fit chart reconstruction; reconstruction sees the source visual only.
- New locales bind to their source, label dictionary and normalized QA. Existing
  bound locales are rejected if these inputs change. The offline audit traces
  legacy locales without binding fields through their saved API records.
- An API request hashes the exact image byte buffer it sends. Cached results must
  identify the same request. A source-bound request with another case's image
  fails before network access.
- Query-polish overlays must match case ID, language, original query, input
  template and protected labels. The source lock cannot be overwritten on resume.
- Render completion is tied to the spec, labels and renderer versions, plus the
  actual PNG hash. Changed inputs trigger rendering; previous images and layout
  records are archived. Legacy exports must still match their previously embedded
  code constants and saved image manifest; otherwise rerendering is required.

## Mixed visuals and answer validity

An image-only table can also contain a diagram, colored markers, legends or other
graphics. The extraction prompt requires `non_tabular_visuals`; a nonempty value
stops the plain-table path with `mixed_visual_requires_full_reconstruction`.
Legacy extraction warnings describing a radial/circular diagram also stop that
path. These elements must receive a complete reconstruction and visual review;
turning their labels into table footnotes does not preserve answerability.

Model extraction can miss a visual element, so this guard is not a substitute for
source-versus-render review. No universal pixel-level semantic guarantee is claimed.
Existing frozen images are not silently regenerated by these code changes, and
running evaluations continue to use their saved inputs. Repairs belong in a new
dataset revision, with new image hashes, renewed review and new inference for the
affected variants. Do not silently attach old predictions to changed images.

The shaper also distinguishes character coverage from script-layout support:
Arial Unicode contains Telugu/Bengali characters but lacks their GSUB/GPOS scripts.
Dedicated Kohinoor Telugu/Bangla fonts are preferred when available; override their
paths with `MVISQA_TELUGU_FONT` and `MVISQA_BENGALI_FONT`. These system fonts are
recorded, not redistributed. Previously frozen images are unaffected until an
explicit new revision is rendered.

The original reference answer can be reused only when the rendered evidence and
query preserve the original question's meaning and answer. A matching ID alone is
insufficient. Upstream annotation errors and reconstruction defects require
separate adjudication; model mistakes do not justify altering benchmark answers.

## Repairing a mixed table and diagram in a new revision

`repair_mixed_visual.py` repairs the identified Visual-TableQA case
`f476b80b56c559558e3e`. It uses the configured API for source reconstruction, QA
normalization, all translations, and visual/semantic review. Recovery receives no
question or reference answer. The `render_mode: custom` contract preserves a
table's dataset category while executing a complete adapter for its accompanying
diagram. Plain table extraction must still reject mixed visuals.

```bash
python -m scripts.final_benchmark.repair_mixed_visual recover
# Inspect proposed_mixed_spec.json, including python_code, before execution.
python -m scripts.final_benchmark.repair_mixed_visual baseline
python -m scripts.final_benchmark.repair_mixed_visual translate
python -m scripts.final_benchmark.repair_mixed_visual audit
python -m scripts.final_benchmark.publish_case_repair
```

Defaults read `final_128_24lang_v1` and write `final_128_24lang_v2` under
`data/visual_benchmark/`; `--parent` and `--output` override both. The first stage
copies the parent if needed. API calls are cached by request fingerprint. A failed
source review blocks translation; unresolved localization issues remain explicitly
flagged in the candidate split. Publishing verifies review fingerprints, executes
all 24 repaired standalone renderers, and preserves the other 127 cases and their
QA records. `invalidated_evaluation_inputs.json` lists the 70 configurations that
need fresh model inference; old evaluation runs and their images remain unchanged.
